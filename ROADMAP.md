# Roadmap

`tail-jsonl` is a lean stdin pipe filter: `<anything> | tail-jsonl` pretty-prints JSONL logs with
Rich colors. It sits in the same pipe as `kubectl logs`, docker, and local dev servers emitting
structlog/pino/LogTape output. The nearest peers are [klp](https://github.com/dloss/klp) (Python,
ergonomics-focused, though its README now points at the Rust rewrite Kelora and calls klp
unmaintained) and [hl](https://github.com/pamburus/hl) (Rust, performance-focused).

## Guiding principles

- Stay a stdin filter. File following, multi-file time-merge, and indexing are `hl`/`lnav` territory
- Optimize per-line streaming latency at human log rates, not batch throughput. Python+Rich cannot
  win lines/sec against Rust and should not try. The benchmark harness (`pytest-benchmark`, plus a
  10k-line throughput script) puts numbers on this: a simple record renders in roughly 190 us, a
  20+ key nested one in roughly 800 us, and a mixed corpus streams at roughly 2,800 lines/sec.
  Comfortable for a live pipe, slow for a large backlog
- Filter before rendering. A discarded line should never pay Rich formatting cost
- Prefer stdlib and existing dependencies. A new runtime dependency needs a benchmark or a feature
  that cannot be reasonably built without it
- Fewer flags, better defaults. Zero-config recognition of common emitter key conventions
  (structlog, pino, zap, LogTape) is the tool's core UX

## Now

Nothing in flight. Open gaps, in priority order:

1. Decide whether `docs/README.md` should go into calcipy_template's `_exclude`.
   `skip_if_exists_files` only protects locally modified files during `run_update`, so a template
   change still overwrites it as-is
2. The changelog is regenerated by `./run main`, not by `./run release`, so releasing means running
   `commitizen changelog` by hand. calcipy 6.1.0rc0 fixes this and writes the changelog after the tag
   so the entry carries the new version. This project still pins `calcipy>=6.0.1` (6.1.0 has not
   reached final), and uv skips prereleases, so adopting the fix means allowing the prerelease or
   waiting for 6.1.0 final
3. `commitizen changelog` prints `Invalid version tag: 'archive/…'` seven times, once per archived
   branch tag. Harmless, and silenceable with a `tag_format` that excludes them
4. Numeric levels carry no color or ordering. An opt-in scale (`--level-scale pino`) would fix that
   for the emitters that use one, and only an explicit flag can disambiguate 30
5. `--min-level` lists `exception` among its choices because that is corallium's name for level 50.
   Accurate, and noise in `--help`
6. An epoch renders as `2024-03-01T12:30:45.123000+00:00`, padding microseconds the emitter never
   sent. Trimming needs a rule for how much precision to keep

## Later, if demand appears

- Match highlighting (`-H/--highlight`). The ecosystem has a real gap (tailspin highlights but does
  not parse JSON)
- Multi-line payload rendering: pretty-print `exception`/`error.stack`/embedded-JSON fields as real
  tracebacks and indented blocks. Weak across the entire ecosystem and a natural fit for the Python
  dev-server audience. Needs a design spike before committing

## Not planned

- Context lines (`-A/-B/-C`). Niche (only klp has it). Use `grep -C` before the pipe or klp for
  offline analysis
- Statistics summaries (`--stats`). A different job (angle-grinder, lnav SQL)
- Theme registry (`--theme`, `--list-themes`). Styles are already configurable via the TOML config.
  Document example style configs (including a catppuccin one) in docs instead of shipping a
  registry, and honor `NO_COLOR`
- Time-range filtering (`--since/--until`), file follow mode, compressed input. All pull toward
  file-oriented workflows that `hl` and `lnav` already own
